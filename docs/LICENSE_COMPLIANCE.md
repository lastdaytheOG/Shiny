# Licence compliance

How Shiny meets the licences of the code it contains, what was checked, and what is still open.
Last reviewed 4 October 2026.

This is an engineering record, not legal advice. Each statement is labelled:

- **Verified**: read from the licence file, the notice or the package metadata itself.
- **Inferred**: concluded from git histories and file comparison, in a provenance audit that the
  project's owner keeps outside the repository.
- **Needs legal/provenance review**: not settled; do not treat it as fact.

The machine-readable sources are `NOTICE`, `LICENSE` and `licenses/`. The build copies those same
files into every APK under `assets/legal`. The app shows no licence pages of its own:
*Settings → About → Source code* opens the repository, where they are read.

## 1. GPL-3.0 obligations

Shiny as a whole is distributed under the GNU General Public License, version 3 (`LICENSE`).

| Obligation | How it is met | Status |
| :-- | :-- | :-- |
| Keep the licence with the work (§4) | `LICENSE` is the unmodified GPL-3.0 text. It ships in the APK (`assets/legal/LICENSE`) | Verified |
| Appropriate copyright notice and no-warranty notice (§4) | `NOTICE` carries both and ships in the APK (`assets/legal/NOTICE`) | Verified |
| Keep existing notices intact (§4, §5) | Every upstream notice in a source file is kept (section 8). `UpstreamNoticesTest` fails if one changes | Verified |
| Say the work is modified, with a date (§5(a)) | `NOTICE`: "Shiny is a modified work. The Shiny Project has modified the code base since 7 September 2026". Files with an upstream notice that Shiny changed in substance say so (section 9) | Verified |
| License the whole work under GPL-3.0 (§5(c)) | No Shiny file carries another licence for Shiny's own code. Third-party parts keep their own, compatible licences (sections 3 to 7) | Verified |
| Appropriate Legal Notices in the interface (§5(d)) | The interface Shiny inherited displayed none, in which case §5(d) does not require adding them. *About → Source code* opens the repository, which holds the licence, the notices and the warranty disclaimer | Inferred |
| Corresponding Source for every APK conveyed (§6) | Procedure in sections 11 and 12. **Not yet in effect**: the repository is private and `shiny.sourceCodeUrl` is unset | Open |

## 2. Upstream provenance

- Shiny's code derives from a line of GPL-3.0 players: InnerTune, then Metrolist, then vivi-music
  and later forks in that line. Shiny's first commit (7 September 2026) imported an
  existing GPL-3.0 code base from that line. Code from ArchiveTune and Convx, and Metrolist's use
  of MusicRecognizer and vibra, came with it. *Inferred*, from the projects' public git histories.
- All of these projects publish their code under GPL-3.0. *Verified* from their repositories'
  licence files as recorded in the audit.
- `NOTICE` credits InnerTune, Metrolist, vivi-music, ArchiveTune, Convx, MusicRecognizer and
  vibra, and says that portions are copyright their respective authors. It does not name every
  project in the line: see section 10, item 3.
- The project's development history since that first commit is kept by the owner and has not been
  rewritten. It is the record of origin.
- Since the import, Shiny has removed or independently rewritten much of the code that was first
  written in the code base it was imported from. Some of it remains (section 10, item 3).

## 10. Needs legal/provenance review

1. **Corresponding Source is not public yet.** The repository is private and has no releases,
   while `shinymusic.in/download` redirects to its releases page. Until the source of a given APK
   is publicly available, that APK should not be handed out. A private repository does not
   provide source to the people who receive the APK.
2. **Uncommitted work.** `NOTICE`, `licenses/`, this file and several hundred other changes are
   not committed. No commit yet matches any APK that has been built.
3. **The project the code base was imported from is not credited by name.** This is the owner's
   decision. No file in the tree carries that project's copyright notice (section 8), so no
   notice of its was removed. Code first written there does remain: the Android Auto additions,
   restore safety and CSV preview in backup/restore, the Room migrations and scattered glue.
   Whether its authors must be credited by name in `NOTICE` is **Needs legal review**. Its
   public history begins at a squashed commit, so which of those lines are its own cannot be
   established from public history either.
4. **`GlassEffect.kt`.** It carries a vivimusic notice, and the audit traces it to Convx, a
   vivi-music fork. The notice is kept as found.
5. **Francesco Grazioso's stream-client work** (`Fix403.kt`, parts of `YTPlayerUtils.kt`,
   `PlayerConfigStore.kt`) was published as a Metrolist-based patch. It is credited in `NOTICE`
   under Metrolist.
6. **Servers run by other projects.** Artist videos use ArchiveTune's artwork service
   (`artwork-archivetune.koiiverse.cloud`). This is a question of permission and terms of use,
   not of copyright licence.
7. **Icons and other drawables** came with the upstream trees and were not audited one by one.
8. **Website artwork.** The promotional site shows third-party album covers. Outside the app,
   but it is distributed publicly.
9. **FFmpegKit and LGPL-3.0** (section 7).
10. **Android Auto additions and backup/restore** are the largest remaining blocks of that code;
    their rewrite is not done.
11. **AI-assisted code.** Much of Shiny's own code was written with an AI assistant. That does
    not change the GPL obligations; what it means for Shiny's own copyright depends on
    jurisdiction.

## 11. Source-code distribution procedure

1. Commit everything the release needs, including `NOTICE`, `LICENSE`, `licenses/` and this file.
2. Make the source of that commit publicly available: a public repository, or a source archive
   on a public page.
3. Check that `shiny.sourceCodeUrl` in `gradle.properties` is that public https address. This is
   the one place the address is set, and it is what *About → Source code* opens. It currently
   names the GitHub repository, which is still private.
4. Run `./gradlew verifyReleaseSource`. It refuses a build with no public address, an unknown
   commit, or uncommitted changes. It checks only; it publishes nothing.
5. Build the release from that commit and tag the commit with the version.
6. Keep the source for that tag available for as long as the APK is offered.

Nothing in the repository publishes, pushes, tags or changes visibility by itself.

## 12. Matching an APK to its source

- Every build records the commit it was made from (`BuildConfig.GIT_COMMIT`) and whether the
  working tree had uncommitted changes (`GIT_TREE_DIRTY`).
- A release is built from a tagged commit and published under that tag, so the tag names the
  source of the APK. `verifyReleaseSource` refuses a build from a modified tree, because no commit
  holds exactly its source.
- The source of an APK is the repository at that tag, including `licenses/`, which is where the
  licence files inside the APK come from.
- After a dependency change, run `python scripts/third_party_licenses.py` and commit `licenses/`.
  `LicenseInventoryTest` fails while the inventory is out of date.
